MongoDB Lab

Build a small shop database in mongosh. Query BSON documents, update nested fields, summarize products, and join orders to the product catalog.

1. Documents and collections

MongoDB stores documents in collections. A collection is roughly comparable to a SQL table, a document to a row, and a field to a column. A document can hold scalars, nested documents, and arrays. MongoDB stores these values as BSON, which supports types such as dates and ObjectIds alongside the types familiar from JSON.

Every document in a regular collection has an _id that identifies it. MongoDB supplies an ObjectId when you omit _id. This lab uses readable string IDs for products so that you can see exactly what an order references.

Documents in a collection can have different fields. Here, phones and tablets have a nested specs document, while chargers omit it. Applications can enforce required fields and types with schema validation.

2. Connect to MongoDB

Use a running local MongoDB server or the Atlas deployment provided for your class. For a local server on the default port, run this command in your system terminal. For Atlas, use the shell command from your deployment’s Connect dialog. See the mongosh connection guide for setup details.

mongosh "mongodb://127.0.0.1:27017"

Run the remaining code blocks inside that same mongosh session, in order.

3. Select a practice database

Start with an empty database for this lab. The first insert creates the database and collection if they do not exist. To repeat the lab from the beginning, choose a fresh database name in the block below.

db = db.getSiblingDB("mongodb_shop_lab");
print(db.getName());

4. Insert documents

Use insertOne() for one document and insertMany() for an array of documents. Each price is numeric, and each tags field is an array of strings.

printjson(db.products.insertOne({
  _id: "laptop", name: "Laptop", price: 1200, tags: ["electronics", "sale"]
}));

printjson(db.products.insertMany([
  {
    _id: "phone", name: "Phone", price: 800, tags: ["electronics", "sale"],
    specs: { color: "black", memory: "128GB" }
  },
  {
    _id: "tablet", name: "Tablet", price: 600, tags: ["electronics"],
    specs: { color: "white", memory: "256GB" }
  },
  { _id: "charger", name: "Charger", price: 40, tags: ["accessory"] }
]));

print(db.products.countDocuments({})); // 4

5. Filter, project, and sort

In find(filter, projection), the filter plays the role of SQL’s WHERE. The projection chooses the fields to return, like the SQL SELECT list. Set _id: 0 to omit the ID. find() returns a cursor, and toArray() collects its results for these small examples.

// Like SELECT name, price FROM products WHERE price > 700 ORDER BY price DESC.
printjson(db.products.find(
  { price: { $gt: 700 } },
  { _id: 0, name: 1, price: 1 }
).sort({ price: -1 }).toArray());

// Dot notation reaches the memory field in the specs document.
printjson(db.products.findOne(
  { "specs.memory": "128GB" },
  { _id: 0, name: 1 }
));

// A scalar equality filter on an array checks for a matching element.
printjson(db.products.find(
  { tags: "sale" },
  { _id: 0, name: 1 }
).sort({ name: 1 }).toArray());

Expect Laptop and Phone in the first result, Phone in the second, and Laptop and Phone in the third.

6. Update and delete documents

$set assigns field values, and $inc adds to a numeric field. MongoDB operator names are case sensitive. The dotted path in the first update changes the color while preserving specs.memory. Check matchedCount, modifiedCount, and deletedCount in the results.

printjson(db.products.updateOne(
  { _id: "phone" },
  { $set: { price: 850, "specs.color": "blue" } }
));

printjson(db.products.updateMany(
  { price: { $lt: 1000 } },
  { $inc: { price: 50 } }
));

printjson(db.products.deleteOne({ _id: "tablet" }));
printjson(db.products.findOne({ _id: "phone" }));

The first update modifies one document. The second modifies three. The delete removes Tablet. Phone now costs 900 and has blue color and 128GB memory.

To replace the entire document body, use replaceOne(filter, replacement). An upsert, requested with { upsert: true } on an update or replacement, inserts a document when the filter matches none.

7. Create an index and inspect the query plan

An index can help MongoDB locate matching documents or return them in order. A compound index orders its entries by the first field and then by the next field. The example below also creates an index for queries that filter by color and then sort by price.

printjson(db.products.createIndex({ price: 1 }));
printjson(db.products.createIndex({ "specs.color": 1, price: 1 }));
printjson(db.products.getIndexes());

printjson(db.products.find({ price: { $gt: 700 } })
  .sort({ price: 1 })
  .explain("executionStats"));

Look for IXSCAN (index scan) or COLLSCAN (collection scan) in the plan. Compare the number of documents examined with the number returned. A dataset this small is useful for reading the plan.

8. Summarize data with an aggregation pipeline

A pipeline passes the output of one stage to the next. $match filters the input. $group combines documents by a key, like SQL’s GROUP BY. Use _id: null for one group containing every matched document. In a pipeline expression, "$price" refers to the price field.

printjson(db.products.aggregate([
  { $match: { price: { $gt: 700 } } },
  {
    $group: {
      _id: null,
      count: { $sum: 1 },
      avgPrice: { $avg: "$price" },
      maxPrice: { $max: "$price" }
    }
  }
]).toArray());

// Emit one document per tag, then count the documents for each tag.
printjson(db.products.aggregate([
  { $unwind: "$tags" },
  { $group: { _id: "$tags", count: { $sum: 1 } } },
  { $sort: { count: -1, _id: 1 } }
]).toArray());

The first pipeline returns one group with count 2, average price 1050, and maximum price 1200. The second returns electronics and sale with count 2 each, then accessory with count 1.

9. Embed order details and reference products

Embed data you usually read together, such as an order’s line items and customer details at the time of purchase. Reference data that has its own lifecycle, such as products in a shared catalog. Each productId below stores the same value and BSON type as the corresponding product’s _id. The application is responsible for keeping these references valid.

printjson(db.orders.insertOne({
  _id: "order-1001",
  customer: { name: "Alice", email: "alice@example.com" },
  items: [
    { productId: "laptop", quantity: 2 },
    { productId: "phone", quantity: 1 }
  ]
}));

$elemMatch requires both conditions to hold for the same array element. The Phone line has quantity 1 and the Laptop line has quantity 2. This query returns an empty array.

printjson(db.orders.find({
  items: { $elemMatch: { productId: "phone", quantity: { $gte: 2 } } }
}).toArray());

$lookup performs a left outer join and returns the matches in an array. Here $unwind first creates one document per line item. The result shows the catalog name and current price for each line. To preserve the price at purchase, store it in the line item when the order is placed.

printjson(db.orders.aggregate([
  { $match: { _id: "order-1001" } },
  { $unwind: "$items" },
  {
    $lookup: {
      from: "products",
      localField: "items.productId",
      foreignField: "_id",
      as: "product"
    }
  },
  {
    $project: {
      _id: 0,
      productId: "$items.productId",
      quantity: "$items.quantity",
      product: { name: 1, price: 1 }
    }
  },
  { $sort: { productId: 1 } }
]).toArray());

Expect a Laptop line with quantity 2 and catalog price 1200, and a Phone line with quantity 1 and catalog price 900. Each product array contains one catalog match.

11. How MongoDB runs across servers

A replica set keeps copies of the same data on several servers. The primary accepts writes and secondaries copy the changes. If the primary becomes unavailable, an eligible secondary can be elected when a majority can communicate. Reads directed to a secondary can lag behind the primary.

Sharding distributes a collection’s documents across shards using a shard key. Replication gives you redundant copies, while sharding distributes storage and work. A single document write is atomic. MongoDB also supports transactions across documents on replica sets and sharded clusters.
